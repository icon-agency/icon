ICON Design System

ICON Design System

A living reference for the design tokens and components behind the ICON Agency build. The Home template is the canonical page; everything catalogued here maps to a Single Directory Component for the Drupal Canvas build. This page is an internal guide, not a production template. Demos wear the production CSS — the same css/main.css the site ships.

Foundations

Every design value flows through a token. Raw colour values exist in exactly one file (src/theme/colors.css); type, spacing, radius and motion are type, spacing, radius and motion are Tailwind v4 @theme custom properties in src/theme/, with the newest tokens — the voice roles, the fluid --space ramp, --gutter-page and --rule — as plain :root properties consumed by component CSS rather than generated utilities.

Colours

Chips below are painted with the live tokens, so they re-resolve when the theme flips — use the toggle (bottom-right), which now cycles THREE themes: light → dark (.dark) → blue (.theme-blue, a brand-blue page with white ink). Values noted as text are the light-theme values; dark values in brackets. Brand aliases invert in dark and flip to white on blue; --color-brand-blue deliberately never re-themes.

    Rules — THE hairline

    Every divider on the site is 1px solid var(--rule) and nothing else — no ad-hoc alphas. --rule follows the theme's border token on ordinary surfaces; a component sitting on a brand or near-black panel re-points it at --rule-on-color (28% white — the same value the blue theme already uses for --border), so the weight reads the same on every ground. Deliberately a plain, unregistered property: the registered --color-* aliases resolve at :root and inherit their resolved value, so a component-level override of those would silently do nothing (see LESSONS.md). Thickness and the draw-in entrance are --rule-weight / --rule-draw-dur in src/utilities/rules.css.

  • Icon grey--color-icon-greyicon-black @ 80%
  • Icon blue--color-icon-blue#0000ff (dark: white @ 80%)

Fixed — never re-theme

ONE black and ONE blue. The raws (--black #0d0d0d, --blue #0000ff) are the single source for every black-ish and blue-ish role: the theming --icon-* tokens above read them in light and override per theme; the fixed roles below read them and never flip. The system previously carried three of each — two hand-synced duplicate literals and a shader blue that had drifted to its own #142cfe — consolidated Aug 2026. shader-blue survives as a ROLE name (the menu/footer shader) wearing the one blue.

    Tracking — the display-caps rule

    All uppercase display headings share one tracking token: --tracking-caps (−0.015em) — the hero lockup, the work titles and the category caps on this page all read it, so big caps sit consistently tight everywhere. Deliberate exception: small uppercase micro-labels (eyebrows, news categories, nav links, arrow-links) keep their wider per-role tracking — tight tracking at label sizes hurts legibility.

    Wrapping & the lockup rule

    Theme-aware component roles also live in colors.css and are overridden per theme: --nav-bg-scrolled (the frosted nav pill), --pager-surface / --pager-surface-strong (pager prev + status pill), and the work-article accent pair --work-article-text / --work-article-bg (per-route override in the v0 build).

    Voice roles — reach for these before inventing a size

    Five named voices carry most of the canonical pages' running text. --voice-mid — THE "sentence" size (hero client label + counter, intro statement, expertise links, work tile titles, both "More" links, the footer's blurb / Subscribe / cities / socials): clamp(1.4rem, 2.1vw, 3.4rem), medium weight, −0.01em tracking, 1.2 line-height — titles and More links run one step heavier (semibold). --voice-meta — the quiet line under it (card categories and dates, work meta, footer place names, filter labels): clamp(1.0625rem, 1.1vw, 1.75rem). --voice-display — the big caps mastheads (WORK, NEWS & INSIGHTS, LET'S TALK) AND the intro statement, one curve and literally one token (.intro aliases it, so the two can never drift): clamp(2.4rem, 5.6vw, 9rem), paired with --voice-display-lh (0.82) for stacked caps and --voice-display-lh-sentence (0.72) for the sentence-case mastheads. All three keep growing to the ~2545–2590px "4xl horizon" before capping. The display voice replaced a wordmark cap-height derivation (reasoning preserved in src/theme/typography.css); --logo-h survives as the wordmark's own FLUID height (the stepped ladder is retired — the mark now scales with the page, ink-aligned to the nav) and the sticky offsets derive from it. A fourth voice joined Aug 2026: --voice-label — chrome and wayfinding (the nav pill, mobile menu labels, arrow-links): clamp(0.78125rem, 0.3rem + 0.5vw, 1.125rem), bold, uppercase — named because the nav used to ride --text-xs, which the homepage re-scopes larger, so the header changed size per page. And a fifth: --voice-headline — the headline register a step under display, above the prose h1 (the article titles and the /news h1 masthead, which left the display voice for it — user call: masthead = article headline): clamp(2.25rem, 3.6vw, 6rem), capping at the same 4xl horizon — and its 1.5× sibling --voice-headline-lg (clamp(3.375rem, 5.4vw, 9rem)): header B's stacked title AND the /news h1 masthead, which stepped up to it (user call: masthead = the article H1's size).

    Fluid ramp — one slope family

    Every margin/padding/gap picks a step from --space-3xs … --space-2xl instead of inventing its own clamp — previously ~18 ad-hoc slopes (several in vh, which collapsed on wide-short screens) froze by ~1400px while the type kept growing. The ramp's steps share a slope family and all reach their cap at ~2300px, so space and type grow together on big monitors. Global :root, not page-scoped, because the footer consumes it from OUTSIDE <main> — an undefined var() there silently invalidates whole shorthands.

    --gutter-pageclamp(1rem, 3vw, 3rem)full-bleed page gutter — the edge padding a viewport-wide section carries when it skips the capped container (listings, articles, the home work section); the same literal had spread across eight files before it was named

    Intro — strip

    Site header

    .site-header — the global chrome (src/components/site-header.css + js/header.js, a faithful port of v40-1’s navigation-bar.tsx / site-logo.tsx): fixed wordmark top-left, desktop pill nav, mobile icon controls, full-screen mobile menu. One token squares the corner — --header-control (3.5rem) sizes the mobile button squares AND the wordmark, so the logo is always exactly as tall as the buttons — and --header-gutter (1.5→3rem across the breakpoints) is the header’s own side gutter, deliberately NOT --container-pad: the header hugs the edge tighter than the content grid, and anything that must line up with the wordmark (the hero’s client name) reads the token instead of re-deriving the number. Scroll drives the chrome: past 10px the pill frosts (--nav-bg-scrolled + 24px backdrop blur, -webkit- first per LESSONS); past 100px the hero-exit swap — the wordmark slides up behind its own anchor’s overflow mask (the hero lockup’s masked reveal, 0.62s decelerating; a ONE-SHOT transition toggled by JS at the same line the glyph appears, so it runs to completion instead of scrubbing with scroll and never strands half-way) while the home glyph expands into the pill and the mobile home button fades in. Pages without header.js simply keep the wordmark. The pill right-aligns from 768 to clear the wordmark and centres at EVERY desktop width now: in the 768–900 band it earns the centre by compressing (tighter link padding, the scroll-revealed home glyph suppressed) with its offset a max() of true centring and the wordmark’s clearance — and the wordmark itself is smaller and fluid (--logo-h), its letterform tops ink-aligned to the nav text by calc, so the two scale together Over a dark hero a page toggles .is-over-hero (js/home-c.js, IntersectionObserver) to force light-on-dark whatever the theme, and the frosted pill dark-tints so the white links still read.

    Live — the pill nav

    The real pill subtree wearing the production CSS — staged without its .site-nav positioner, which is position: fixed at z-index 10000 (and display: none below md): it would escape the dashed stage and sit over this page’s own chrome.     Parallax, lean & tilt — why they are not demoed here

    One image, three property owners — the crop-zoom reveal drives scale, the scroll parallax drives transform (a −3%→3% translate + 1.05 zoom on the frame’s named view timeline --work-media, compositor-driven, never a scroll handler), the hover brighten drives filter — so all three compose on one element without fighting. The cursor tilt (±2.2°, js/home-c.js 3f) therefore lands on the FRAME, never the image, fed by --mx/--my written on the ITEM and inherited down — declaring them on the frame would shadow the inherited value and pin the tilt at zero. The scroll-velocity lean (3e, gsap) rotates every tile up to 2.5° with the sampled scroll speed (full lean at 2600px/s, decaying as the scroll settles, lerped only while the section is near the viewport) — capped low because a tile is about half the container wide, so a bigger angle swings its corners into the neighbour. All of it is tuned against the full-page document scroll; a scaled inline copy would misrepresent it. Open the real thing:

    Sized by container — the 26rem split

    The homepage gives a card the full container width; /news gives it half of one. A viewport query would have to guess which — the same 1024px would mean a 938px card on one page and a 650px card on the other — so the card asks its own box instead: below the threshold it stacks, above it splits. The threshold is 26rem (416px), set by the tightest box this card is ever asked to split in: the homepage’s news rail halves its own column at min-width: 1024px, dropping the host <li> to ~452px — ~445px once a classic scrollbar takes its 15px. Anything above that stacks the homepage cards through the whole 1024–1230px band, where they have always sat side by side; a value just under 452 would have flipped on any machine that reserves scrollbar gutter. 26rem clears the scrollbar case with room to spare. An element cannot query itself, so the breakpoint sits on the PARENT — declared by the component as :has(> .news-card) { container-type: inline-size }, so it carries its own contract and neither list has to know. Deliberately not li:has(...): a Drupal Views row wraps each teaser in <article>, and a selector keyed to <li> would silently stop matching, no container would be established, and every @container rule would go dead. The split rides a three-feature chain (:has() → container-type → @container), so @supports not (container-type: inline-size) falls back to the viewport rule this component replaced (min-width: 640px) — wrong only in the narrow band the container query exists to get right. Same discipline in the type: in the 768–1024 band the title’s 1.5vw curve floored at 20px exactly where the card’s box is widest for the screen, so a banded cqi clamp lifts it there — anchored to meet the floor right at the 416px split, and banded rather than global because a container term strong enough for tablets would lift the desktop rails MORE.

    Reveal primitives

    The four shared entrance gestures every page composes — the [data-animate] fade-up, the .reveal-lines masked line rise, the .media-reveal crop-zoom and the [data-rule] hairline draw — under one contract: the hidden state lives behind a root .js-animations class (stamped by an inline head script on real pages), js/reveal.js toggles one latched class per element from an IntersectionObserver, and the CSS owns every transition and stagger.     [data-animate] — the fade-up host

    Opacity 0 plus a 20px rise, transitioning on --duration-slow / --ease-standard, with a per-element stagger via --animate-delay (it is just the transition-delay). js/reveal.js adds .is-visible once (threshold 0.1, bottom rootMargin −50px) and unobserves — latched, so an entrance always plays out in full and never re-runs. It is the generic companion to js/work.js, which only drives its own [data-reveal] swipes, underlines and hover-video — the /work and /work/article page chrome revealed nothing until this file. No IntersectionObserver in the browser? Everything is revealed immediately. Under reduced motion the CSS resets the host to visible with no transition, so the class toggle is inert.

    .reveal-lines — the masked line rise

    The hero lockup’s gesture, packaged: each line waits below its own overflow-hidden mask and rises on a stagger (0.62s --ease-decelerate, delay --w × 0.2s) rather than the block fading up as one. Used by the sentence-case landing mastheads — both “News & Insights” and the /work landing’s “Work” (the homepage rail and the /news h1). It rides the [data-animate] host for its trigger — both on the same element — and cancels the host’s own fade: two gestures on one element read as a stutter, and the mask is the one doing the work. The geometry is a coupled pair. The mask carries asymmetric padding-block: 0.14em 0.30em (taken straight back off in margin) — a cap above, Miller’s sentence-case “g” below at the tight 0.72 sentence leading, where 0.24em clipped 1.5px, measured. And the word rests at translateY(155%), not 100%: it must clear the MASK, which the descender pad made taller, while translateY is relative to the line box the tight leading shrank — at 135% the resting glyphs sat 0.1px below the edge (measured); 155% buys ~8px of certainty, and the extra travel is imperceptible over 0.62s. Move the pad or the leading and you re-measure the travel — they move together. The footer’s LET’S TALK repeats these values under its own classes because it hangs off .is-revealed, which re-arms every time the panel is entered, not the fire-once [data-animate] — same values, different clock.

    .media-reveal — the crop-zoom

    The media inside a .media-reveal frame starts as a bottom-left sliver — clip-path: inset(84% 84% 0 0 round var(--radius-icon)), scale 1.12, transform-origin: left bottom, opacity 0 — and opens up-and-right to the full frame on .is-revealed (clip 1.1s + scale 1.3s on --ease-decelerate, opacity 0.6s). The invariant: the effect stays on the MEDIA, never on the observed [data-reveal-img] frame — a transform or clip on the observed element skews its own IntersectionObserver ratio, so the frame keeps its full box while overflow: hidden plus a fixed aspect-ratio contain the zoom and nothing nudges the caption (see LESSONS.md). The same rule re-declares the filter transition it would otherwise out-specify and drop, keeping the work/news hover-brighten alive. The observer was lifted into js/reveal.js at its third consumer — js/home-c.js and js/news.js each carried an identical copy and the news article made three (threshold 0.18, bottom rootMargin −8%, latched). Sibling primitive: .split-line, the overflow-hidden wrapper GSAP SplitText puts around each line for the homepage’s line-mask text; its base rule keeps the text visible if JS or SplitText never runs.

    [data-rule] — the hairline draw

    THE hairline: every rule on the site is 1px of --rule — the theme’s border token on ordinary surfaces, --rule-on-color on the dark and brand panels, because a white line is invisible on white: the same decision expressed twice, not an inconsistency. --rule-weight and --rule-draw-dur (0.7s) make thickness and speed single edits, so the whole page draws at one speed. A rule marked [data-rule] (top / bottom / both) arrives by growing from its left edge: the 1px border survives for LAYOUT but is painted transparent, and the visible line is a background gradient sized 0 → 100% across the border box. Nothing moves when it runs — the box is the same height before and after — which is why a gradient and not a pseudo-element overlay: several of these sit in grids and lists where a re-layout would shove content around mid-scroll. both (the footer’s last office row) is two gradients, two sizes, one transition. Rules already drawn as pseudo-elements (the clients marquee’s pair) opt in via [data-rule-host] and read --rule-draw 0 → 1, scaling from a left origin instead. One observer in js/reveal.js covers the lot — bottom rootMargin −5% and NO threshold ratio, because a ratio of a 1px line would never fire. Latched, not toggled: a rule is a structural line between two pieces of content, and re-drawing it on every re-entry would make the page feel like it was still loading. Degradation runs one way only: no-JS and reduced motion read “always drawn”, never “never drawn” — a rule that never arrives would take content with it (the news list’s rows are separated by these).
