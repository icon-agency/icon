ICON Design System

ICON Design System

A living reference for the design tokens and components behind the ICON Agency build. The Home template is the canonical page; everything catalogued here maps to a Single Directory Component for the Drupal Canvas build. This page is an internal guide, not a production template. Demos wear the production CSS — the same css/main.css the site ships.

Foundations

Every design value flows through a token. Raw colour values exist in exactly one file (src/theme/colors.css); type, spacing, radius and motion are Tailwind v4 @theme custom properties in src/theme/.

Colours

Chips below are painted with the live tokens, so they re-resolve when the theme flips — use the toggle (bottom-right) to inspect the dark palette. Values noted as text are the light-theme values; dark values in brackets. Brand aliases invert in dark; --color-brand-blue deliberately never does.

Semantic roles

The shadcn-style role set (background, foreground, border, muted, …) is mapped through @theme inline, so a runtime .dark class on <html> re-themes without a rebuild. Per-route overrides rebind on <html>, never <body> (see LESSONS.md).

  • Background--color-backgroundwhite (dark: #1e1e1e)
  • Foreground--color-foregroundnear-black (dark: near-white)
  • Border--color-borderneutral hairline
  • Muted foreground--color-muted-foregroundsecondary text

Tracking — the display-caps rule

All uppercase display headings share one tracking token: --tracking-caps (−0.015em) — the hero lockup, the work titles and the category caps on this page all read it, so big caps sit consistently tight everywhere. Deliberate exception: small uppercase micro-labels (eyebrows, news categories, nav links, arrow-links) keep their wider per-role tracking — tight tracking at label sizes hurts legibility.

--tracking-capsDemocracy cards campaign−0.015em

Wrapping & the lockup rule

text-wrap: pretty is the default on all content; balance only where asked for (currently the work titles). The hero lockup's caps are sized so the WHAT/MATTERS letter height matches the ICON wordmark's letter height at each logo breakpoint — do not grow the lockup for wide screens; the logo caps at 1536px, so the lockup does too.

Containers — a settled decision

The site default is .u-container: a 90rem (1440px) cap with a fluid gutter. The homepage deliberately breaks it — .page-home uncaps the container entirely (theonecentre-style: the composition keeps expanding on ultra-wide screens, held in only by a gutter that scales to ~120px, with type ceilings raised to match). Settled with the client-side of the build; do not re-cap the homepage.

Motion

Three easings and four durations cover the interface. Hover a row to run its easing. Policy: scroll-linked movement runs on the compositor via CSS scroll-driven animations (animation-timeline) — never a scroll handler; one-shot entrances are class-triggered transitions so they always play out in full; everything is reduced-motion guarded. GSAP (SplitText) and Lenis are page-level enhancements on the homepage, not requirements.

Components

Each block below is (or will be) one SDC in the Drupal Canvas build — the BEM block, CSS file, SDC folder and field prefix share a root name; variants are a single enum prop. Sections land here incrementally; sidebar entries are uncommented as each ships.

Hero

.hero — full-bleed 100svh stack takeover (promoted from the approved Hero experiment, 02): the work pieces pop in at the viewport centre one by one and shrink onto a small snapshot pile; after a 0.5s beat the last scales up to cover the viewport and hands off to a reel — 3s per piece, 0.1s cross-fades, videos playing while active, stills on a subtle Ken Burns, client name small in the bottom-left. The real-text "Make what matters" lockup (Miller italic + Kumbh 800, three centred lines) rises word-by-word the moment the takeover completes, and plays out in reverse order on scroll.

Why it is not demoed here

The hero is timed choreography — the pop-and-stack load sequence, the takeover, the reel and its cross-fades, the lockup cascade, header inversion. A scaled inline copy would misrepresent all of it. Open the real thing:

Drupal (Canvas / SDC)

SDC hero. Props: headline (the lockup is markup-built from it) and pieces — a list of work items, each with a media file (image or video) and a client name; the template renders each piece TWICE, once as a .hero__card in the pile and once as a .hero__slide in the reel. No variants. Behaviour js maps to Drupal.behaviors.iconHome (pop/stack sequence, takeover, reel, exit trigger, header inversion) — each card waits on its own media before popping, and reduced motion skips the choreography and runs the reel with hard cuts. The sr-only real text is the accessible name; the lockup, pile and reel are all aria-hidden.

Intro — strip

.intro — the approved Strip experiment (weareboring.nl reference): the transparent logo-mark video (tinted to ink), a centred sentence-case headline, then a full-bleed draggable filmstrip of tilted photos. The strip drifts on an infinite GSAP marquee; dragging straightens the cards and leans them with the drag velocity before momentum decays them back to their scattered tilts; hover stalls the drift and straightens the hovered card while a DRAG badge chases the cursor. Below, the band (statement + About left, expertise ledger right) scrolls naturally — only the “Our expertise” label locks: sticky against the viewport, it holds while the list slides up past it, and whichever item sits beside it is inked. Hovering an item slides the name right, then fades a “/” in just before it, both in accent blue.

Live

Real markup wearing the production CSS. This page loads no page JS or GSAP, so this is the genuine no-JS state: the cards rest on their CSS --r tilts (the strip scrolls natively instead of drifting), the word cascade doesn’t run, and the first expertise item is inked by the no-JS fallback. The logo video and the “/” hover (CSS-only) do work here. The sticky “Our expertise” label and its scroll-highlight need the page-length scroll, so the label just rests in place in this stage; the stage also neutralises the strip’s real-viewport full-bleed and hides the fixed DRAG badge.

News article

.news-article — the full news story page (templates/news-article.html, design: experiments/News-article.png). Full-bleed on the shared --gutter-page. The page opens dark and hands over to light as the head’s halfway point scrolls past — two-way, so the return scroll restores the dark opening — with every hairline reading --rule-on-color while dark. The head is a ruled column (Share opens it, the meta line closes it on the photo’s baseline) beside a square photo; the body is a symmetric grid — a sticky Share rail, a centred ~67ch prose measure that scales with its own 1.2vw body copy to the 4xl horizon, and a phantom right column so the prose centres on the PAGE, not the flow. Wide figures break out between prose chunks; upright serif statements (.pull-quote--upright) divide the acts; a “Next up” teaser rail reuses the homepage news block under its own rule.

Why it is not demoed here

The page IS its scroll choreography — the theme handover, the sticky rail, the media reveals and hairline draws. A scaled inline copy would show none of it honestly. Open the real thing:
