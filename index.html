ICON Design System

ICON Design System

A living reference for the design tokens and components behind the ICON Agency build. The Home template is the canonical page; everything catalogued here maps to a Single Directory Component for the Drupal Canvas build. This page is an internal guide, not a production template. Demos wear the production CSS — the same css/main.css the site ships.

Foundations

Every design value flows through a token. Raw colour values exist in exactly one file (src/theme/colors.css); type, spacing, radius and motion are Tailwind v4 @theme custom properties in src/theme/.

Colours

Chips below are painted with the live tokens, so they re-resolve when the theme flips — use the toggle (bottom-right) to inspect the dark palette. Values noted as text are the light-theme values; dark values in brackets. Brand aliases invert in dark; --color-brand-blue deliberately never does.

Semantic roles

The shadcn-style role set (background, foreground, border, muted, …) is mapped through @theme inline, so a runtime .dark class on <html> re-themes without a rebuild. Per-route overrides rebind on <html>, never <body> (see LESSONS.md).

  • Background--color-backgroundwhite (dark: #1e1e1e)
  • Foreground--color-foregroundnear-black (dark: near-white)
  • Border--color-borderneutral hairline
  • Muted foreground--color-muted-foregroundsecondary text

Wrapping & the lockup rule

text-wrap: pretty is the default on all content; balance only where asked for (currently the work titles). The hero lockup's caps are sized so the WHAT/MATTERS letter height matches the ICON wordmark's letter height at each logo breakpoint — do not grow the lockup for wide screens; the logo caps at 1536px, so the lockup does too.

Containers — a settled decision

The site default is .u-container: a 90rem (1440px) cap with a fluid gutter. The homepage deliberately breaks it — .page-home uncaps the container entirely (theonecentre-style: the composition keeps expanding on ultra-wide screens, held in only by a gutter that scales to ~120px, with type ceilings raised to match). Settled with the client-side of the build; do not re-cap the homepage.

Motion

Three easings and four durations cover the interface. Hover a row to run its easing. Policy: scroll-linked movement runs on the compositor via CSS scroll-driven animations (animation-timeline) — never a scroll handler; one-shot entrances are class-triggered transitions so they always play out in full; everything is reduced-motion guarded. GSAP (SplitText) and Lenis are page-level enhancements on the homepage, not requirements.

Easings

Components

Each block below is (or will be) one SDC in the Drupal Canvas build — the BEM block, CSS file, SDC folder and field prefix share a root name; variants are a single enum prop. Sections land here incrementally; sidebar entries are uncommented as each ships.

Hero

.hero — full-bleed 100svh media hero with the real-text "Make what matters" lockup (Miller italic + Kumbh 800, sized to the logo), word-by-word cascade in, triggered word-by-word exit on scroll (reverse order), image parallax and a picture-in-picture campaign video.

Why it is not demoed here

The hero is scroll choreography — load cascade, triggered exit, compositor parallax, header inversion. A scaled inline copy would misrepresent all of it. Open the real thing:

Drupal (Canvas / SDC)

SDC hero. Props: headline (the lockup is markup-built from it), media (image or video), pip_video (optional). Behaviour js maps to Drupal.behaviors.iconHome (load sequence, exit trigger, header inversion). The sr-only real text is the accessible name; the lockup is aria-hidden.

Intro statement

.intro — the two-part editorial opener: a small uppercase lede with the "/"-prefixed expertise list stacked beneath it (left, 5→4→3 columns as the viewport widens), and the big fluid statement at columns 7–12. The two blocks align on their first-line baselines (align-items: baseline on the grid), not their tops — the small and large type start on the same line.

Live

Real markup wearing the production CSS. On the homepage the section spans the uncapped container with raised type ceilings; here it wears the site-default tokens at the pane's width. The demo stage supplies --grid-gutter the way the page layer does on the homepage. Without page JS the reveals simply don't run — the no-JS state you see is the real fallback.
